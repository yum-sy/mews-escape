# Pokémon — Mew’s Escape · Phase 4 complete demo

[게임 실행](https://yum-sy.github.io/mews-escape/)

Phaser 3 + TypeScript + Vite로 만든 팬 게임 웹 데모입니다. 원래 명세의 마지막 단계인 Phase 4까지 구현했습니다. B6부터 B1까지 올라가는 6개 층·56개 방, 뮤츠 3단계 전투와 엔딩, 저장·이어하기, PWA 오프라인 캐시가 연결됩니다. 상점 등 초기 명세의 확장 후보는 추가하지 않고 기본 플레이의 완성도를 우선합니다.

## 탐험과 상호작용

- 층별 격리 장치, 표본 선반, 독성 탱크, 공명 코일, 통제 콘솔, 무너진 지상 출입구의 색·조명·바닥 구조가 달라집니다. 기물 그림자, 바닥 격자, 균열, 끊어진 케이블, 부유 먼지가 공간을 구성합니다.
- 공격으로 작은 상자·용기를 부수면 잔해와 효과음이 남습니다. 통행을 막거나 보상을 무한 생성하지 않습니다.
- 전투 중에도 차단기에 접근해 시설 함정을 끌 수 있습니다. 적의 공격이나 독 장판은 계속 위험합니다.
- 방을 정리하면 문이 열리고 중앙에 기술 캡슐이 나타납니다. 캡슐을 직접 열어 3지선다 보상을 선택합니다. 받지 않은 캡슐은 미니맵에 표시되며 재방문·이어하기로 받을 수 있습니다.
- 해당 층의 전투방과 팬텀을 정리한 뒤 승강기에서 직접 작동해야 다음 층으로 이동합니다.
- 가까운 대상에 E / 상호작용 버튼이 표시됩니다. 기록은 안전한 방에서 읽을 수 있으며 게임 설명의 보관함에 수집됩니다.
- 파손·차단·기록 조사 상태는 체크포인트에 저장됩니다. 기존 버전의 진행 저장도 읽을 수 있습니다. 전투 중의 변화는 다음 체크포인트 때 확정됩니다.

## 조작

|입력|기능|
|---|---|
|WASD / 왼쪽 스틱|이동|
|방향키 / 오른쪽 스틱|8방향 / 360도 공격, 유지하면 연속 발사|
|E / 가까이에서 표시되는 버튼|캡슐·차단기·기록·승강기 사용|
|Esc / 정지 버튼|일시정지·재개|
|소리 버튼|게임 음악과 효과음 켜기·끄기|

## 전투와 성장

19종의 기술·강화가 누적됩니다. 처음 선택한 공격 방식이 유지되고, 서로 다른 계열의 공격은 동시에 합성됩니다. 주 공격 55%와 보조 공격 전체 45%로 직접 피해 예산을 나누며 유도·관통·화상·중독·연쇄·흡수 등은 모든 계열에 누적됩니다. 같은 계열의 기술은 효과를 더합니다. 원치 않는 보상은 회복 없이 포기할 수 있습니다. 화염방사는 짧고 넓은 지속 불줄기, 냉동빔은 긴 관통 빔, 물대포는 물줄기, 기가드레인은 흡수 줄기, 환상빔은 맥동 광선, 전기 기술은 즉발 방전입니다.

트라이어택은 모든 탄을 맞혀도 단일 줄기 대비 합산 직접 피해 65% / 2단계 50%, 스피드스타는 55% / 2단계 40%입니다. 둘은 곱해져 1단계 조합 35.75%, 양쪽 2단계 20%입니다. 상태 효과를 넓게 전달하는 대신 직접 화력을 포기합니다. [합성·오디오·밸런스 설명](docs/GAMEPLAY-PRESENTATION.md).

적의 도감 키와 PNG 불투명 영역에 맞춰 표시 크기와 충돌 반경을 구성합니다. 층이 올라갈수록 적과 시설의 위협이 증가하며, 뮤츠 HP 420 / 520 / 640의 세 단계를 통과해야 엔딩에 도달합니다. 단계 사이 자동 회복은 없습니다.

## 저장·설치·기록

같은 브라우저의 localStorage에 방 진입·클리어·보상 선택·보스 단계 등을 저장합니다. 전투 중 재접속하면 체크포인트부터 방/단계를 다시 시작합니다. 죽거나 엔딩을 마치면 현재 진행은 삭제되며, 클리어 횟수·최고 도달 층·최고 처치·최단 성공 시간·연구 기록은 별도로 남습니다. 영구 능력치 강화나 계정 동기화는 없습니다.

설치 화면에서 플랫폼별 PWA 설치 방법과 오프라인 준비 상태를 확인할 수 있습니다. 기존 창을 닫은 뒤 새 버전 서비스 워커가 활성화되어 진행 중인 게임을 강제 재시작하지 않습니다.

## 실행·검증

Node.js 22 이상에서 `npm install`, `npm run dev`, `npm test`, `npm run build`를 사용합니다. main push 시 GitHub Actions가 테스트·빌드·Pages 배포를 수행합니다. `?seed=3`은 재현 가능한 던전, 개발 서버의 `?qa`는 검증용 버튼, `?campaign`은 정상 규칙 자동 조작기이며 배포 번들에서는 제거됩니다.

[전체 진행·성능 검증](docs/PLAYTEST-QA.md), [완성도 검증 기록](docs/COMPLETION-QA.md), [보류/처리한 피드백](docs/FEEDBACK.md), [이야기](docs/STORY.md)를 참고하세요. 정상 규칙 자동 조작으로 B6부터 엔딩까지 확인했습니다. 모바일 실기기별 장시간 FPS·설치 및 사람의 난이도·승률 검증은 별도이며, 자동 조작이나 데스크톱 화면 크기 검증으로 이를 대신했다고 주장하지 않습니다.

리소스는 로컬 제공하며 플레이 중 API를 호출하지 않습니다. Pokémon 이미지·Kenney 타일·생성된 오프닝 소재의 출처는 `public/assets/CREDITS.txt`, `Kenney-LICENSE.txt`, 관련 출처 JSON에 보존했습니다. 이번 환경 개선은 기존 타일과 코드로 그린 도형을 사용했습니다.
